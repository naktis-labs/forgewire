# ADR-0001 implementation inventory

Reference: `TheStranjer/foundry-vtt-mcp` commit `c117882be3922346e4df873d6268d65ddbc68997`. This is a source inventory, not evidence that live Foundry operations work. E = exposed, P = partial, M = missing, D = intentionally restricted.

Updated after the shared-operations and connection-lifecycle increments. Evidence is fixture-based unless stated otherwise.

| Capability | MCP | REST | Evidence and remaining work |
| --- | --- | --- | --- |
| World metadata | P | P | Shared operation exposes selected world fields, safe author details and bounded module metadata. The allowlist intentionally omits author email and other potentially sensitive fields and excludes collection bodies; top-level release generation and build are exposed, while other release and world-package metadata remain unexposed; bounded descriptions may be truncated. Live payload compatibility remains unverified. |
| Collection reads | E | E | Shared operation; both call the connector. |
| Single lookup, filters, projection, byte limits | E | E | Shared `read` operation with contract tests asserting identical connector calls and results. |
| Compendium list and document reads | E | E | Shared operation; contract-tested. |
| Compendium create/delete | E | E | Shared operation over the identity's persistent connection, write gate enforced before validation and connector contact. A compendium change whose outcome is unknown is reported like any other change: 502 with `"outcome": "possibly_applied"`. |
| Document create/update/delete | P | P | Shared `write_document` over the identity's persistent connection; strict ACK validation, ambiguity reporting. A change whose outcome is unknown is its own typed outcome (`PotentiallyApplied`), not a plain upstream failure: the REST envelope adds `"outcome": "possibly_applied"` and the change is never replayed. Exercised against the disposable world, including an authenticated end-to-end change; live mutations unverified. |
| Instance listing/selection | P | P | Listing shared and secret-free. REST targets an instance explicitly with `?instance=<id|item_order>` or the stable first-entry default; there is no process-global REST selection endpoint. MCP selection is scoped to a server-issued `Mcp-Session-Id` session (bounded table, unknown sessions get 404, headerless selection is refused). Contract tests cover REST default and explicit targets, per-session MCP isolation, and that an MCP selection never moves REST's default. Selection is not connection-verified; live multi-instance behavior unverified. |
| Browse files | E | E | Shared operation over the identity's persistent connection; a REST/MCP divergence on the `kind` parameter was found and fixed. |
| Upload caller-provided bytes | D | D | Shared operation; bounded size, explicit overwrite acknowledgement, ambiguous-outcome reporting. Input the connector refuses before it reaches Foundry is a caller mistake (`400`), not an upstream fault. |
| Upload from remote URL | M | M | Deferred by ADR-0001 pending a separate SSRF and egress security decision. |
| Username-only or userid-only credential | E | E | Resolved against Foundry join-user data, exact match preferred with unique case-insensitive fallback, ambiguous or inconsistent identities fail closed. |
| Persistent authenticated socket | P | P | One authenticated connection per identity serves every operation kind — world and document reads, document changes, compendium management and file browsing — with a distinct acknowledgement id per request, so concurrent requests share one socket without being confused for one another. Bounded map, idle reaper, cancellation quarantine, write deadlines, namespace-disconnect handling, redacted credential `Debug`, 64 MiB frame limit. Bounded reconnect with jitter and connection epochs apply to connection establishment, not replay of in-flight requests; a change is never replayed and reports an ambiguous outcome instead. An upstream refusal (an error acknowledgement, or an answer of an unexpected shape) fails only its own request and leaves the shared connection in use; only a transport failure invalidates the connection. An acknowledgement that carries a request's id is that request's answer even when its shape does not fit, so such an answer fails the request instead of leaving it waiting. The connection is established before the world slot is taken, so a slow handshake no longer consumes a world request's own response budget. Bounded unsolicited events are collected internally. `Retry-After` is honored for transient upstream statuses in its delta-seconds form, and an unsuccessful session GET is now terminal rather than retried. Stale-reader integration coverage remains timing-dependent. |
| Optional insecure TLS | M | M | Documented compatibility gap; secure default retained. |

Evidence base: 200 workspace tests using a loopback fake Foundry (authentication fields, v13 and v14 session binding, identity resolution, interleaved ACKs, world `430` handling, cancellation and late responses, one socket shared by reads, changes, compendium management and file browsing, ambiguity when a socket drops during a change, a slow handshake that does not consume the world request budget, an upstream refusal that keeps the shared connection usable, an honored `Retry-After` hint that does not hide the upstream message, a refused session request that is not retried, a world request that waited through a broken socket and retried on the new one, a refusal that leaves a request in flight alone, a transport failure that invalidates the connection, a hint that does not carry over to a later attempt, and a change with an unknown outcome reported as possibly applied, end to end through the real connector and the REST write route, the same outcome for compendium changes, the `Retry-After` cap, the reconnect deadline, and a change refused before it reaches Foundry answering `400`, end to end through the real connector and the REST upload route). REST/MCP contract tests use a recording fake connector; the interoperability harness drives the real connector, including an authenticated change, against the disposable world.

The current `FoundryClient` does not enable a reqwest cookie jar; the ADR baseline's shared-cookie-jar concern does not apply to this source. Session and connection state are isolated per identity by HMAC-keyed map entries.

Existing REST routes are preserved and extended: `GET /health`, `GET /api/world`, `GET /api/collections/{name}`, `POST /api/write/{operation}`, plus document, compendium, instance and file routes. MCP uses `POST /mcp`. All write paths are exercised against the disposable world only; live Foundry behavior still requires separately authorized verification.
